# 开发环境

本仓库已经是可编译的 Fabric 工程。41 只玩偶已入仓并注册（摆件、创造栏、外观头槽）。`runClient` / `runServer` 用来确认 Loader、前置和本模组能一起起来。Gradle 工程名 `rootProject.name` 是 `BC-s-Furnishings-Decor`（对齐 GitHub）；模组 id 仍是 `bcs_furnishings`，jar 仍是 `bcs-furnishings-decor-*.jar`。

## 怎么跑

目录名里有 `&`。`gradlew.bat` 已改成带引号，cmd 和 Java 语言服务都能用；PowerShell 仍可用 `gradlew.ps1`。

**F5** 启动客户端测试（配置名 `Minecraft Client`）。走 Gradle `runClient`，不走 Debugger for Java：语言服务经常认不成 `bcs-furnishings-decor`，F5 会被拦。JEI、玉、mezz_config、Mod Menu 走 `modRuntimeOnly`，F5 和 `runClient` 都会加载。不要写进玩家 `depends`。

```powershell
Set-Location -LiteralPath "D:\Working Directory\BC's Furnishings & Decor"
.\gradlew.ps1 runClient
```

其它常用：`.\gradlew.ps1 build`、`.\gradlew.ps1 runServer`。命令面板任务 `runClient` 和 F5 是同一条命令。

- Gradle / Loom 用本机 **JDK 25**（`C:\Program Files\Java\jdk-25.0.2`），写在 `gradle.properties` 的 `org.gradle.java.home`。
- 模组字节码和游戏进程是 **Java 21**（toolchain）。
- 测试存档在 `run/`，不进 Git。
- IDE：`.vscode/settings.json` 让 Gradle 用 JDK 25、工程用 JDK 21。改完 Java 配置后若问题栏还显示 `non-project file`，命令面板执行 **Java: Clean Java Language Server Workspace** 再重载窗口。
- 工作区里其它工程（例如 PvpArena）的 Java 报错已在 `paper插件.code-workspace` 里排除，不进本模组问题栏。

| 模组 | 坐标 / 版本 | 游戏内 id |

Trinkets 3.11 自己 JIJ 了 CCA 7.3.0 的 base/entity。另外再装 7.3.2 整包时，Loader 用 7.3.2，没有撞 id。Cosmetic Armor 的 `depends` 写的是 `trinkets`，所以必须用 Patbox 这档（它还叫 `trinkets`），不能换成 id 为 `trinkets_updated` 的 26.x 构建。

## 验证过什么

`.\gradlew.ps1 build` 通过。`runServer` 用 Loader 0.19.5 拉起 1.21.11，日志里有 `bcs_furnishings`、GeckoLib、Trinkets、Cosmetic Armor、CCA 7.3.2、JEI、Jade；Java 21。Mod Menu 是客户端模组，服务端不会出现。玩偶类在 common；渲染器在 client。`DollBlockItem.createGeoRenderer` 和玉的 `registerClient` 用反射调 client 钩子，专用服务端不加载 `ITooltip` 那些客户端类。

## 不要动

- 不要把 Loom 换成 26.x 的 `net.fabricmc.fabric-loom`（无重映射）。
- 不要把 Loader 擅自升到 0.20.x。
- 不要加 Cloth Config 当玩家前置。
- Nucleoid Maven 上的 `eu.pb4:trinkets` 目前没有 1.21.11 的 3.11，不要改回那条坐标。
